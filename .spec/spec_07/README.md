# spec_07 會議室預約：照 Figma 和 PM 需求做出前端畫面

你會拿到 UX 的 Figma 截圖（含使用者操作流程圖）和這份 PM 需求文件，要用 React 做出一個可以實際操作的會議室預約網頁。沒有後端，所有資料都存在瀏覽器裡。

## 先看這裡：兩份資料說法不同時聽誰的

Figma 截圖和這份文件說法不一樣時，**以這份文件為準**。

```text
Figma 截圖（畫面、流程） ──本文件補充並修正──► 你的實作
```

Figma 是設計稿，有些地方還沒跟上最新決定。本文件的每條規則都要做到，就算 Figma 畫的不一樣。

## 這個產品要解決什麼

公司有 5 間會議室，同事現在用共用試算表登記，常常撞期。這一期要做一個網頁，讓你：

1. 在時間表上看某一天每間會議室的空檔
2. 直接在時間表上選時段，填表預約
3. 修改自己的預約：用表單改，或在時間表上拖曳卡片邊框調整時間
4. 在「我的預約」查看、修改和取消自己的預約

登入不在這一期的範圍：目前使用者固定是「王小明」。

## 功能需求

### 時間表（01）

- **R-01** 時間表顯示 08:00–20:00，每格 30 分鐘，每列是一間會議室。
- **R-02** 點一格空白格，就開啟預約表單，自動帶入該會議室和那 30 分鐘。在同一列拖曳選取連續的空白格，就帶入整段時間。選取不能跨過已被預約或已過去的格子。
- **R-03** 篩選條件有三個：日期、參與人數、設備。設備可以多選，會議室要符合所有選到的設備才顯示。沒有任何會議室符合時，顯示空狀態和「清除篩選」按鈕。
- **R-04** 篩選條件要同步到網址的 query string。重新整理，或把網址分享給別人打開，畫面上的日期和篩選要一樣。query 的格式由你決定。
- **R-05** 目前時間的紅線每分鐘更新一次。已過去的時段不能選。
- **R-06** 瀏覽器寬度小於 768px 時，時間表改成「先選會議室，再顯示當天時段的直向列表」。Figma 沒有畫手機版，請沿用桌面版的風格自己設計。

### 預約表單（02、03）

- **R-07** 欄位規則。錯誤訊息顯示在欄位下方，樣式照 02 的錯誤狀態：

  | 欄位 | 規則 |
  |---|---|
  | 會議主題 | 必填，去掉前後空白後 1–50 字 |
  | 日期 | 今天起 14 天內（含今天） |
  | 開始、結束時間 | 在 08:00–20:00 之間，以 30 分鐘為單位；結束要晚於開始；長度 30 分鐘到 4 小時；開始時間不能早於現在 |
  | 參與人數 | 整數，1 到該會議室的容量 |
  | 備註 | 選填，最多 200 字 |

- **R-08** 送出時檢查同一會議室的時段有沒有重疊。時段剛好相接不算重疊，例如 10:00 結束和 10:00 開始。有重疊就顯示 03 的衝突畫面：
  - 列出同一時段有空、容量也大於等於參與人數的其他會議室，依容量由小到大排列，最多 3 間
  - 一間都沒有時，顯示「同時段沒有其他可用的會議室」
  - 點「改預約這間」會換成那間會議室，其他欄位保留，讓使用者再送出一次
- **R-09** 同一個人在同一時段只能有一筆預約，換會議室也一樣。違反時在表單上方顯示「你在這個時段已經有預約：<會議室> <時間> <主題>」。
- **R-10** 用前端模擬 API：
  - 送出後等約 800ms 才有結果。這段期間按鈕顯示 loading，而且不能重複送出
  - 會議主題包含 `[500]` 時，模擬伺服器錯誤：表單內容保留，顯示錯誤 toast「預約失敗，請稍後再試」
  - 預約成功後關閉表單、顯示成功 toast，時間表馬上出現這筆預約

### 我的預約（04）

- **R-11** 只列出還沒結束的預約，依開始時間由近到遠排列。這一期只做這個列表，不需要其他分頁。
- **R-12** 取消預約前要跳確認 dialog。確定後移除這筆預約，並顯示 toast「已取消預約」。會議開始前 30 分鐘內（包含已經開始的），「取消預約」按鈕要 disabled，旁邊寫「開始前 30 分鐘內無法取消」。

### 修改預約（06）

- **R-16** 只能修改自己的預約，有兩個入口：
  - 在時間表上點自己的預約卡片
  - 在「我的預約」每一列，「取消預約」右邊的「修改」按鈕

  點別人的預約卡片不會開表單，只顯示 tooltip。
- **R-17** 修改表單沿用新增表單的版面，樣式照 06：
  - 標題是「修改預約」，欄位帶入這筆預約原本的資料，送出按鈕是「儲存變更」
  - 沒有改任何欄位時，「儲存變更」是 disabled
  - 欄位規則（R-07）、衝突檢查（R-08、R-09）、模擬 API（R-10）都跟新增一樣；檢查衝突時不要跟這筆預約自己比
  - 儲存成功後關閉表單，顯示 toast「已更新預約」，時間表和「我的預約」馬上更新
- **R-18** 會議開始前 30 分鐘內（包含已經開始的）不能修改：「修改」按鈕 disabled；時間表上點這張卡片不開表單，也不能拖曳邊框。「修改」和「取消預約」都 disabled 時，說明文字改成「開始前 30 分鐘內無法修改或取消」。

### 拖曳邊框調整時間（07、08）

- **R-19** 在時間表上，滑鼠移到自己的預約卡片時，左右邊框出現把手；游標移到邊框上變成左右箭頭（`ew-resize`）。拖左邊框改開始時間，拖右邊框改結束時間：
  - 以 30 分鐘為單位對齊格線
  - 拖曳時在卡片上方顯示新的時間和長度，例如「11:00–13:00（2 小時）」
  - 手機版（R-06 的直向列表）改成拖上下邊框
- **R-20** 拖到不能再拖的地方時，邊框停住、不能再往前，旁邊用紅字寫原因。邊框停住後放開，就用停住的時間儲存。

  | 碰到什麼 | 說明文字 |
  |---|---|
  | 同一會議室前面的預約 | 前面是「<主題>」<開始>–<結束>，不能再提早 |
  | 同一會議室後面的預約 | 後面是「<主題>」<開始>–<結束>，不能再延後 |
  | 08:00 或 20:00 | 可預約時間是 08:00–20:00 |
  | 現在時間 | 開始時間不能早於現在 |
  | 長度下限或上限 | 每次最短 30 分鐘、每次最長 4 小時 |

- **R-21** 新的時段跟自己在其他會議室的預約重疊時（R-09），使用者在這一列看不到那筆預約，所以不擋拖曳，改成顯示錯誤狀態：
  - 卡片變成紅色，旁邊寫「你在 <會議室> 已有「<主題>」<開始>–<結束>」，那筆預約的卡片也標紅
  - 拖回不重疊的位置，錯誤狀態就消失
  - 在錯誤狀態下放開，卡片回到原本的時間，不儲存，並顯示 toast：標題「時間沒有變更」，內容「你在這個時段已有其他預約」
- **R-22** 放開後直接儲存，不用再確認：
  - 卡片顯示 spinner 和「儲存中…」，這段期間不能再拖；走 R-10 的模擬 API
  - 成功時顯示 toast：標題「已更新時間」，內容是會議室和新的時間
  - 失敗時（主題包含 `[500]`）卡片回到原本的時間，顯示錯誤 toast：標題「更新失敗」，內容「請稍後再試」
  - 拖曳中按 Esc 取消，卡片回到原本的時間；放開時時間沒變就不送出

### 全站

- **R-13** 資料存在 localStorage，重新整理後還在。第一次開啟時寫入幾筆示範預約：日期以「今天」為基準，要有別人的也要有自己的，而且至少一筆在今天。頁尾放「重置示範資料」按鈕，按下後清掉現有資料，重新寫入示範預約。
- **R-14** 鍵盤和無障礙：
  - Esc 可以關閉 modal 和 dialog
  - modal 開著時，Tab 的焦點只在 modal 裡面移動；關閉後焦點回到原本點的那個元素
  - 狀態不能只靠顏色區分，例如「我的預約」和「已過去」都要有文字或圖示
- **R-15** 「今天」和「現在」用瀏覽器當下的時間；時間一律用 24 小時制。

## 交付方式

三件事一定要記得：

1. 必須重新做一個新的，不准參考 repo 裡其他 `preview-*` 成品
2. 你只能依據這份文件和這個資料夾裡的 PNG
3. 開始時先在 repo 根目錄建立工作資料夾 `preview-wip/`，並記下開始時間；所有產出和暫存檔都放在裡面

成品是一個資料夾，入口是裡面的 `index.html`：

```text
preview-wip/          開始時建立，做完後改名
├─ index.html         入口，要有 <title>（GitHub Pages 的列表頁會讀它當標題）
└─ *.jsx、*.css …     要不要拆檔、怎麼拆由你決定
```

完成後把 `preview-wip/` 改名成：

```text
preview-spec_07-${MODEL_NAME}-${TIME_COST_MINUTES}-${FILE_CREATED_AT_YYYYMMDDHHMMSS}/
```

- `MODEL_NAME`：執行本次任務的 model 名稱與版本，版本號用點分隔（例如 `claude-opus-5.5`）；有設定 reasoning effort 時接在後面（例如 `-xhigh`），沒有就省略。去掉 provider 前綴（例如 `anthropic/`），`[A-Za-z0-9._-]` 以外的字元換成 `-`
- `TIME_COST_MINUTES`：從開始到改名當下的經過時間，單位分鐘，無條件進位成整數
- `FILE_CREATED_AT_YYYYMMDDHHMMSS`：改名當下的本機時間
- 範例：`preview-spec_07-claude-opus-5.5-xhigh-42-20261110153005/`

技術限制：

- 用 React 寫，元件用 JSX
- 不能有打包或編譯步驟，例如 webpack、Vite、tsc。用 CDN 載入 React 18 的 UMD build（例如 `react@18.3.1`、`react-dom@18.3.1`）和 `@babel/standalone`（例如 `@babel/standalone@7.29.10`），讓瀏覽器直接執行 `<script type="text/babel">` 裡的 JSX
- 可以拆成多個 `.jsx` 檔，用 `<script type="text/babel" src="...">` 載入。瀏覽器看不懂 JSX，所以 `.jsx` 檔之間不能直接用 `import` 互相引用；檔案之間怎麼共用程式由你決定
- CDN 版本要寫死；不載入外部圖片和字型；icon 用 inline SVG
- 不能有後端，所有資料都在瀏覽器裡
